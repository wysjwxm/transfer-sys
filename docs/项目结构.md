# 转账系统 · 项目结构文档

> 行内转账（单账户聚合、强一致）的最小可跑样例，兼作支付系统面试与 Spring 原理的练手载体。
> 设计口径、里程碑进度见 `src/main/resources/TODO.md`；本文件只讲「代码怎么摆、为什么这么摆、请求怎么走」。

## 1. 技术栈与硬约束

| 项 | 取值 | 说明 |
|---|---|---|
| JDK | **1.8**（本机唯一） | 决定了 Spring Boot 版本上限 |
| Spring Boot | **2.7.18** | 支持 Java 8 的最后一个大版本 |
| ORM | **MyBatis 原生** | XML 手写 SQL，不用 MyBatis-Plus，展示原生绑定机制 |
| 数据库 | **H2（MODE=MySQL）** | 内嵌、零安装；SQL 只写 H2/MySQL 通用子集，缺 MySQL 不阻断启动 |
| 构建 | Maven 3.9.16 | `spring-boot-maven-plugin` |
| 样板代码 | Lombok | getter/setter/构造器交给编译期生成 |

> 依赖全清单见 `pom.xml`：`starter-web`、`mybatis-spring-boot-starter`(2.3.2)、`h2`(runtime)、`starter-test`；MySQL 驱动被注释，切 `mysql` profile 时恢复。

## 2. 分层架构：DDD 四层

依赖方向**由外向内单向**：`interfaces → application → domain ← infrastructure`。

- **domain（领域层）**：只依赖自身与 JDK，不 import 任何 Spring/MyBatis 类型——这是分层的核心裁判。
- **infrastructure（基础设施层）**：**向上依赖 domain**（实现其 Repository 接口），反向不成立。
- **application（应用层）**：编排领域对象 + 持有事务边界，不含业务规则。
- **interfaces（接口层）**：HTTP 形态转换，只粘合不决策。

```
                    ┌──────────────────────────────────────────────┐
  外            →   │ interfaces  Controller / DTO / 异常兜底       │
                    └──────────────────────┬───────────────────────┘
                                           │ 调用（传 Command，收 Result）
                    ┌──────────────────────▼───────────────────────┐
                    │ application  TransferAppService  ← 事务边界    │
                    └───────┬──────────────────────────┬───────────┘
                            │                          │
                 ┌──────────▼──────────┐      ┌────────▼──────────────┐
                 │ domain（规则/聚合）    │      │ infrastructure       │
                 │ Account/TransferLog │◄─────│ *RepositoryImpl        │
                 │ TransferService     │  实现 │   └ MyBatis Mapper     │
                 │ Repository 接口      │  的   │      └ resources/mapper│
                 │ BizException/ErrorCode│  接口 │         /*.xml        │
                 └─────────────────────┘      └───────────────────────┘
```

## 4. 各层文件职责

### 4.1 启动与配置
| 文件 | 职责 |
|---|---|
| `TransferSysApplication` | `@SpringBootApplication` + `@MapperScan("...persistence.mybatis")` 扫 Mapper 接口 |
| `application.yml` | 数据源(H2 file)、`mybatis.mapper-locations`、下划线转驼峰、`sql.init` 自动建表灌数、日志收敛 |
| `schema.sql` / `data.sql` | `account`、`transfer_log` 两表；账户 1/2 各 1000.00（`WHERE NOT EXISTS` 幂等） |

### 4.2 接口层 `interfaces`
| 文件 | 职责 |
|---|---|
| `TransferController` | `POST /api/v1/transfers`：把 JSON 请求转成应用层 `TransferCommand`（含金额字符串→`BigDecimal` 解析），结果包 `Result` |
| `AccountController` | `GET /api/v1/accounts/{userId}`：查余额 |
| `GlobalExceptionHandler` | `@RestControllerAdvice`：`BizException`→对应错误码；未知异常→5000 + error 日志 |
| `Result<T>` | 统一返回：`code=0` 成功，非 0 见 `ErrorCode`；接口一律 HTTP 200 |
| `TransferRequest/Response`、`AccountResponse` | 进出参 DTO。`amount` 用 String 承载，防 JSON double 丢精度 |

### 4.3 应用层 `application`
| 文件 | 职责 |
|---|---|
| `TransferAppService` | 转账用例编排；**事务边界**（`@Transactional`）；升序加锁；写流水；生成业务单号。只读查询 `getAccount` 走 `readOnly=true` |
| `TransferCommand` | 一次转账的输入对象（from/to/amount/requestNo） |
| `TransferResult` | 用例结果（txnNo 回执） |

### 4.4 领域层 `domain`（不 import Spring/MyBatis）
| 文件 | 职责 |
|---|---|
| `Account` | 账户聚合根。业务方法 `withdraw`/`deposit`/`hasEnough` 内聚"余额非负"规则；Lombok setter 仅供持久层装配 |
| `TransferService` | 领域服务：表达"一次转账"规则（金额>0 / 非自转 / 余额足），**纯内存**无持久化 |
| `TransferLog` | 转账流水实体（整笔一行，后续承载状态/冲正锚点） |
| `TransferLogStatus` | 状态枚举，MVP 恒 `SUCCESS`，预留 |
| `AccountRepository` / `TransferLogRepository` | **仓储接口**：领域层定义，决定依赖倒置方向 |
| `BizException` / `ErrorCode` | 业务异常 + 错误码字典（1001 账户不存在…5000 系统错误） |

### 4.5 基础设施层 `infrastructure`
| 文件 | 职责 |
|---|---|
| `AccountRepositoryImpl` / `TransferLogRepositoryImpl` | `@Repository`，实现 domain 接口，委托给 Mapper |
| `mybatis/AccountMapper` / `TransferLogMapper` | Mapper 接口（无注解），SQL 全在同名 XML |
| `mapper/*.xml` | namespace = Mapper 接口 FQN；`FOR UPDATE` 加锁、`useGeneratedKeys` 回填主键、枚举按 `.code` 落库 |

## 5. 一次转账的调用链

```
POST /api/v1/transfers
  │  TransferController          ① 参数形态转换：DTO → TransferCommand
  ▼                                （String amount → BigDecimal，解析失败抛 INVALID_REQUEST）
TransferAppService.transfer      ② 应用层，进入事务
  │  requireValid                 ③ 基础参数校验
  │  findByIdForUpdate(min)       ④ 按 user_id 升序加行锁 SELECT…FOR UPDATE
  │  findByIdForUpdate(max)          （自转时只锁一次）→ 防交叉等待死锁
  ▼
TransferService.transfer(from,to) ⑤ 领域规则：自转/金额非法/余额不足 → 抛 BizException
  │  from.withdraw / to.deposit     （余额非负由 Account 保证）
  ▼
  │  updateBalance(from)           ⑥ 两笔 UPDATE 回写
  │  updateBalance(to)
  │  insert(TransferLog)           ⑦ 成功才落流水（txn_no 全局唯一）
  ▼
返回 Result{txnNo}
```

- ②~⑦ 在**同一个数据库事务**内：⑤ 任一异常 → 整体回滚（扣款、入账、流水都不落）。
- ④ 两账户按 id 升序加锁 = 死锁预防（不是检测）。
- ⑦ 的 `txn_no` 即回执号，也是日后冲正 / 对账 / 幂等的锚点。

## 6. 关键设计决策速查

| 决策 | 落点 | 备注 |
|---|---|---|
| 行内转账强一致 | 事务边界在 `TransferAppService`，跨聚合 | DDD"跨聚合最终一致"的业务例外 |
| 并发控制 | `SELECT…FOR UPDATE` + id 升序 | 乐观锁下期 |
| 金额 | `DECIMAL(19,2)` + `BigDecimal` | 传输层用 String 防丢精度 |
| 流水策略 | 整笔一行，成功才落库 | 不做借贷双行 |
| 账户维度 | 一人一账户，主键 `user_id` | 一人多账户下期拆 account |
| 幂等 | `request_no` 唯一约束占位 | 防重逻辑未实现 |
| 对外 | HTTP 200 + `body.code` | 国内支付 API 风格 |

## 7. 测试与配置：一个必须知道的坑

- 测试：`TransferFlowIntegrationTest` 用 **`@SpringBootTest` + `MockMvc`** 全链路跑 6 个用例，类级 `@Transactional` 每例回滚互不污染。
- 数据源隔离靠 **profile 覆盖**，不是同名文件覆盖：
  - `src/test/resources/application-test.yml` **只**覆盖 datasource 为 H2 内存库；
  - `src/main/resources/application.yml` 仍是测试时的**基底配置**，`mybatis.mapper-locations` 由此生效；
  - 测试类标注 `@ActiveProfiles("test")`。

> ⚠️ **坑（曾踩）**：若在 `src/test/resources` 放一个**同名** `application.yml`，它会把主配置**整个遮蔽**（test-classes 排在 classpath 前面，只解析第一个 `application.yml`），`mybatis.mapper-locations` 随之消失 → XML 不加载 → 报 `BindingException: Invalid bound statement`。结论：跨环境叠加用 `application-{profile}.yml`，不要用同名文件覆盖。

## 9. 一句话定位各关键类（面试口径）

- **`TransferService` 是领域规则，`TransferAppService` 是事务编排**——问"规则放哪、事务放哪"就答这两个。
- **`Account` 把余额规则内聚成方法**，杜绝散落的 `if (balance < amount)`。
- **`Repository` 接口在 domain、实现在 infra**，是"依赖倒置"那个"倒"字的具体体现。
- **`@MapperScan` + `mapper-locations` + namespace** 三件套 = MyBatis 把 XML 绑到接口的完整机制。
